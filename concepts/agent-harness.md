# 에이전트 하네스 (4기둥 · 규칙 3층)

모델은 그대로 두고 **모델을 둘러싼 것** — 맥락 문서, 규칙, 검증, 피드백 — 을 통틀어 부르는 말. 비유하면 모델은 말, 하네스는 안장과 고삐. 같은 모델이라도 하네스에 따라 결과가 갈린다.

**4기둥** (김영우 「AI 하네스 깎는 노인」)
- **Constraint** — 무엇을 못 하게 하나 (에이전트별 권한 분리 등)
- **Context** — 무엇을 알려주나 (CLAUDE.md, skills, 구조화된 문서)
- **Verification** — 결과를 누가 검증하나 (pre-commit hook, 린터, 테스트)
- **Feedback** — 실패가 어떻게 다음에 반영되나 (자동 수정 루프, 사고 기록)

**규칙의 3층** (NHN Cloud) — 강제력이 약한 것부터
1. **텍스트 규칙** — 하네스에 "하지 마"라고 적는다. 맥락이 복잡해지면 무시당한다.
2. **구조적 강제** — 통로를 하나로 고정한다 (예: DB 접근은 스크립트 하나로).
3. **권한 차단** — 애초에 못 하게 권한을 뺀다 (예: read-only 계정).

**하네스 개선 루프의 안전장치:** 에이전트는 개선을 *제안*(`harness-backlog`)하고, *반영*은 사람이 한다. 에이전트는 자기 오답을 오답인 줄 모르기 때문.

**프롬프트와 다른 점:** 프롬프트는 한 번의 요청이고, 하네스는 세션이 바뀌어도 남는 구조다. "무엇이 적혀 있나"보다 "왜 이렇게 적혀 있나"(결정 기록)가 이식되지 않는 부분이다.
