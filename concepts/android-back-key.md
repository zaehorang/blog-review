# 안드로이드 백키

안드로이드 기기의 **물리/제스처 뒤로가기 버튼**. iOS엔 없다 — 좌상단 back·엣지 스와이프는 앱 UI가 소유하지만, 안드로이드는 **OS가 소유한 전역 back**이 하나 더 있는 셈.

[웹뷰](webview.md)에서 왜 문제냐:

```
안드로이드 백키 누름
   └→ 기본 동작: Activity 종료 = 웹뷰 화면이 통째로 닫힘
        (웹은 자기가 뭘 할 기회조차 없음)
```

그 순간 웹 안에 **바텀시트가 열려 있었다면** 사용자 기대는 "시트만 닫힘"인데 실제론 앱 화면이 통째로 나간다. → 앱이 백키를 삼키지 말고 **브릿지로 웹뷰에 넘기고**, 웹이 "닫을 게 있으면 닫고 없으면 닫아도 된다고 회신"하는 규약이 필요하다.

## 히스토리를 누가 쥐는가

| | 스택 소유자 | 사용자가 직접 조작? |
|---|---|---|
| 네이티브 | 앱 (`UINavigationController.viewControllers` 등) | ❌ 앱이 준 버튼으로만 |
| 웹 | 브라우저 (History API, URL 기반) | ✅ 주소창·뒤로/앞으로·새로고침·링크 복사 |

핵심은 "메모리냐"가 아니라 **웹은 히스토리를 사용자와 브라우저가 같이 쥔다**는 것. 그래서 "모달 열림을 히스토리 엔트리로 올릴까" 같은, 네이티브엔 없는 결정이 생긴다.
