# 행동 평가 (Behavioral Evaluation)

에이전트/모델의 **최종 출력물**이 아니라, 그 결과에 도달하기까지 취한 **이산적이고 관찰 가능한 행동**을 검증하는 평가 방식. "fast, deterministic, unit-style checks that run locally"로, 특정 상황에서 특정 행동을 했는지/안 했는지를 예·아니오로 판정한다.

- 모호한 요청을 받았을 때 되묻는가 (추측하지 않는가)
- 빌드 파일을 고친 뒤, 완료 선언 전에 로컬 validator를 실행했는가
- 문서를 생성할 때 실제 존재하는 원본 링크를 제공하는가

**벤치마크와의 차이:** 종합 벤치마크(예: Terminal-Bench)는 태스크 전체의 성공/실패라는 뭉뚱그려진 점수만 주기 때문에, 점수가 떨어져도 원인(과신? 검증 누락? 환각?)을 알 수 없다. 행동 평가는 실패 지점을 정확히 짚어낼 수 있는 단위로 쪼갠 것 — 벤치마크가 "시험 점수"라면 이건 "시험 볼 때 문제를 다시 읽었는가, 검산을 했는가"를 채점하는 체크리스트에 가깝다.

**단언 작성 기준:** 단순 작업은 툴 호출 시퀀스를 엄격하게 강제해도 되지만("edit 후 validator가 호출됐는가"), 복잡한 작업은 순서를 강제하면 오탐이 늘기 때문에 결과 기반의 느슨한 판정(→ [LLM-as-a-judge](llm-as-a-judge.md))을 쓴다.

**왜 모델이 바뀌어도 자산이 되는가:** 행동 평가는 모델의 능력치를 재는 게 아니라 "우리 팀이 지키기로 한 특정 행동"이라는 도메인 계약을 재는 것이라, 모델 세대가 바뀌어도 그 계약(테스트) 자체는 그대로 유지된다. 반대로 그 계약을 지키기 위해 붙여둔 프롬프트/툴 제약(하네스)은, 새 모델이 계약을 알아서 지킨다면 — 테스트를 유지한 채 그 제약만 빼고도(ablation) 통과율이 유지되는지 확인해서 — 가지치기할 수 있다.
