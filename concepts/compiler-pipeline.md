# 컴파일러 파이프라인

**컴파일러 이론의 표준 패턴**이지 특정 언어 전용이 아니다.

```
Lexer(스캐너) → Parser → Semantic Analysis(바인더·체커) → Codegen(이미터)
```

TS로 옮기면: 스캐너 → 파서 → 바인더 → 체커 → 이미터.

## 언어에 따라 빠지는 단계

- **정적 타입 언어**(C/Java/Go/Rust/TS) — 파서와 코드생성 사이에 **의미 분석/타입 체크 단계가 항상 낀다.**
- **동적 타입 언어**(순수 JS/Python/Babel) — 그 단계가 **통째로 빠진다.**

TS는 기계어까지 안 가고 JS에서 멈추는 **소스-투-소스 트랜스파일러**라서 IR/최적화 단계가 없는, 상대적으로 단순한 파이프라인이다.

⚠️ **체커와 이미터는 별개 단계다.** "체크해서 안전하면 이미터가 변환"이 아니다 — 이미터는 체크 결과와 무관하게 emit한다.
