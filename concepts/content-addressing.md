# 내용 주소화 (content-addressing)

무언가를 **그 내용으로부터 계산한 해시**로 식별하는 방식. "이름"이나 "위치"가 아니라 "내용 자체"가 주소가 된다.

## 위치 주소 vs 내용 주소

| | 키 | 보장 |
|---|---|---|
| 위치 주소 (URL 등) | `https://.../antd.js` | "주소가 같으면 내용도 같겠지" — **믿는다** |
| 내용 주소 (해시) | `sha256(내용) = 7f3a9c...` | "내용이 1바이트라도 바뀌면 키가 바뀐다" — **보장한다** |

## 왜 유용한가
1. **중복 제거 / 재사용:** 같은 해시 = 같은 내용 → 이미 만들어둔 결과를 그냥 쓴다. "전에 처리한 적 있나?"를 O(1)에 판별.
2. **캐시 영구화:** 내용이 바뀌면 주소가 바뀌므로, 캐시 만료를 신경 쓸 필요가 없다(캐시 버스팅). [CDN](cdn.md) 참고.
3. **무결성:** 받은 파일을 다시 해시해보면 변조 여부를 안다.

## 같은 원리를 쓰는 것들
- **git**: 커밋·트리·블롭이 전부 SHA 해시. 커밋 해시가 같으면 히스토리 전체가 동일.
- **Docker 레이어**: 레이어 다이제스트가 같으면 다시 안 받음.
- **빌드 캐시 / 번들러 캐시**: 입력 파일 해시가 같으면 컴파일 스킵.
- **토스 `packageSetHash`**: 패키지 조합을 해시 → 같은 조합이면 S3의 사전 빌드 재사용.

## 해시가 바뀌는 조건 = 그 시스템이 "무엇을 입력으로 보는가"
packageSetHash는 패키지 목록+버전이 바뀔 때. git 블롭 해시는 파일 내용 1바이트라도 바뀔 때. 이 "입력 정의"가 캐시 적중률을 좌우한다.
