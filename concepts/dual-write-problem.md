# 이중 쓰기 문제 (Dual Write)

**서로 다른 두 시스템(예: DB와 메시지 큐)에 같은 사건을 각각 쓰면, 둘을 하나의 트랜잭션으로 묶을 수 없어 한쪽만 반영되는 순간이 생기는 문제.**

## 예시 — "작업을 저장하고 발신 큐에 넣는다"

| 순서 | 중간에 죽으면 | 결과 |
|---|---|---|
| ① DB 저장 → ② 큐 전송 | ①과 ② 사이 | DB엔 `PENDING`, 큐엔 없음. 작업이 영영 안 돈다 |
| ① 큐 전송 → ② DB 저장 | ②에서 DB 실패 | 큐엔 있고 DB엔 없음. 기록 없는 작업이 실행된다 |
| 큐에서 꺼내 실행 → DB 상태 갱신 | 실행 후 갱신 전 | 메시지가 다시 보여 **같은 작업이 두 번** 실행된다 |

## 피하는 길
- **저장소를 하나로 줄인다.** 작업과 상태를 DB 한 곳에 두고, "작업 집어 가기"와 "상태 변경"을 한 트랜잭션으로 묶는다. 처리량 한계가 대가다. (채널톡 콜 캠페인의 선택)
- 그래도 DB 밖으로 나가는 부작용(전화·결제·메일)은 트랜잭션이 못 지킨다. 재시도할지(중복 위험) 말지(누락 위험)를 업무로 정하고 반대쪽을 확인으로 메운다 → [멱등성](idempotency.md).
