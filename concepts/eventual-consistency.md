# 최종 일관성 (Eventual Consistency)

여러 서비스(= 여러 DB)에 걸친 하나의 논리적 상태를, **지금 당장은 안 맞아도 이벤트가 결국 도착해서 처리되면 언젠가는 같은 값으로 수렴한다**고 보장하는 방식.

반대 개념은 **강한 일관성(Strong Consistency)** — 모든 노드가 항상 동시에 같은 값을 봐야 한다는 보장. 분산 트랜잭션(2PC 등) 같은 무거운 조율이 필요하다.

## 왜 필요해지나

MSA에서 서비스마다 DB를 따로 두는 게(Database per Service) 표준 패턴인데, 이 대가로 **여러 DB에 걸친 상태를 원자적으로 못 맞추게** 된다. 두 시스템 사이의 상태 변화가 비동기(예: A가 요청을 보내고, B가 처리 결과를 나중에 이벤트로 돌려주는 구조)라면, 그 사이 잠깐 "A와 B가 서로 다른 상태를 보고 있는 순간"이 반드시 생긴다.

이때 선택지는 두 가지다.

| | 강한 일관성 (동기) | 최종 일관성 (비동기) |
|---|---|---|
| 정확성 | 항상 즉시 일치 | 잠깐의 불일치 구간 존재 |
| 장애 전파 | 한쪽이 느리면 다른 쪽도 블로킹 | 전파 안 됨 (격리) |
| 구현 비용 | 분산 트랜잭션 등 무거움 | 이벤트 처리 + 중복/순서 처리 필요 |

"즉시 일치"를 포기하는 대신 얻는 게 **장애 격리**다. 대가로 떠안는 게 이벤트 재전송 시의 중복·순서 문제이며, 이건 [멱등성](idempotency.md)으로 막는다.
