# 증분 빌드와 피드백 루프

**증분 빌드** = 바뀐 파일 + 그에 의존하는 부분만 재컴파일. 대형 모듈 프로젝트는 클린 빌드 몇 분 vs 증분 몇 초.

**피드백 루프** = `[수정 → 빌드 → 확인 → 수정]` 한 바퀴. 이게 몇 초냐 몇 분이냐가 생산성을 좌우한다.

## 에이전트 맥락에서 특히 중요한 이유

루프가 빠르면 **에이전트가 더 자주 시도하고 스스로 교정한다.** 느리면 한 번에 맞히려 들고, 틀리면 그대로 간다.

그래서 도구를 볼 때 물을 것 — 새 빌드를 맨바닥에서 띄우나, **이미 열려 있는 것을 조작해 캐시(DerivedData 등)를 재활용하나.**
