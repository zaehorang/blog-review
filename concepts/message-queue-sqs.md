# 메시지 큐와 SQS

**보내는 쪽이 "할 일"을 큐에 넣어 두면, 받는 쪽이 자기 속도로 가져가 처리하는 구조.** SQS(Simple Queue Service)는 AWS가 관리해주는 메시지 큐다. 비유하면 시스템이 처리할 투두 리스트.

## 동작
1. 생산자가 메시지를 큐에 넣는다.
2. 소비자가 큐를 **폴링**해서 가져간다(큐가 밀어주는 push가 아니라 pull).
3. 처리가 끝나면 소비자가 그 메시지를 **삭제**한다. 결과를 알려야 하면 DB 상태나 별도 큐를 쓴다(같은 큐에 완료 메시지를 되돌려 보내는 게 기본형은 아니다).

## 보장하는 것과 안 하는 것
- 보장: 메시지를 **잃지 않는다**(안전).
- 기본(Standard) 큐는 **at-least-once** — 같은 메시지가 두 번 이상 올 수 있다. "정확히 한 번"이 아니므로 소비자가 중복을 견뎌야 한다 → [멱등성](idempotency.md).
- 소비자가 처리 도중 죽으면 메시지는 일정 시간(visibility timeout) 뒤 다시 보인다. 그래서 "잃지 않음"과 "중복 가능"이 같이 따라온다.

## 큐를 쓸 때 따라오는 문제
큐와 DB는 다른 시스템이라 둘을 한 트랜잭션으로 묶을 수 없다 → [이중 쓰기 문제](dual-write-problem.md).
