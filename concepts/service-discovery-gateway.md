# 서비스 디스커버리와 게이트웨이 서버

서버가 여러 대·여러 클러스터로 나뉘면 클라이언트나 내부 서비스는 **현재 어느 주소로 요청해야 하는지** 알아야 한다. 서비스 디스커버리는 살아 있는 인스턴스와 위치를 찾고, 게이트웨이는 정책에 따라 적절한 목적지로 안내하거나 요청을 중계한다.

채팅 서비스의 역할을 단순화하면 다음과 같다.

```text
클라이언트
 ├─ API 서버: 로그인, 사용자·대화방·과거 메시지 요청/응답
 ├─ 게이트웨이: 이 사용자가 연결할 소켓 서버 결정
 └─ 소켓 서버: 장기 연결 유지와 실시간 이벤트 송수신
```

API 서버는 짧은 요청 처리량, 소켓 서버는 동시 장기 연결 수, 게이트웨이는 서버 위치·상태·분할 정책이 주요 확장 조건이다. 역할을 나누면 각각 독립적으로 확장하고 장애를 격리할 수 있다.
