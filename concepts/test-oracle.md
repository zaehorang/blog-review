# 테스트 오라클 (test oracle)

테스트에서 "이 결과가 맞다"를 판정하는 **근거**. 기대값이 어디서 나왔느냐의 문제다.

## 오라클 문제
기대값을 **구현과 같은 로직으로 다시 계산**하면, 둘이 같은 오해를 할 때 테스트가 통과한다. 검증이 아니라 복사가 된다. 정책이 바뀌면 서비스와 테스트 두 곳을 고쳐야 하는 유지보수 비용도 따라온다.

## 독립적인 근거의 종류
- **사람이 계산해 둔 표** — CSV에 가입일별 기대 시작/종료일. 느리지만 구현과 독립이다.
- **다른 구현** — 같은 일을 다른 방식으로 푼 참조 구현. 둘이 다르면 어느 쪽이 틀렸는지 조사한다.
- **불변식(성질)** — 값 대신 항상 참이어야 하는 관계를 검사한다. 예: 앵커 복귀 방식이면 "가입일이 28·29·31이어도 2회 결제 총 이용일수는 같다" ([월 반복 결제의 앵커 날짜](billing-anchor-date.md)).

## 왜 중요한가
자동화로 케이스가 빠르게 늘수록 기대값 계산 로직이 구현을 닮기 쉽다. 초록불이 의미 있으려면 틀릴 수 있는 쪽에서 나온 근거여야 한다.
