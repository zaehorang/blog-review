# 윈도잉 / 가상 스크롤 (Windowing / Virtual Scroll)

긴 리스트나 텍스트를 다룰 때, **화면에 보이는 부분 + 위아래 버퍼만 실제로 렌더링**하고 나머지는 크기(높이)만 가진 빈 자리(placeholder)로 남겨두는 기법. 화면 밖으로 나가면 unmount, 화면 안으로 들어오면 mount.

## 핵심 변수 — 버퍼 단위 크기

"화면 근처만 그린다"는 전략은 항상 같지만, **무엇 하나를 mount/unmount 단위로 삼느냐**가 갈린다. 단위를 크게 잡을수록(예: 여러 문단을 묶은 청크, 페이지) 관리할 조각 수는 줄지만:

- 그 단위 **안**의 작은 변화도 단위 **전체**의 [reflow](reflow-repaint.md)를 유발한다 (변경 전파 범위가 단위 크기에 비례)
- 단위보다 작은 granularity의 기능(예: 문단 하나만 선택)을 얹기 어렵다

단위를 작게 잡으면(예: 문단 하나) 이 두 문제는 줄지만, 대신 관리할 조각 수가 늘고 **각 조각의 placeholder 높이를 미리 정확히 알 수 없다**는 새 문제가 생긴다 — 실제 렌더링 전엔 몇 줄이 될지 모르기 때문. 추정치와 실제 높이가 어긋나면 스크롤 위치가 틀어지는 "스크롤 점프"가 발생한다. 보통 글자 수 기반 휴리스틱으로 우선 추정하고, mount될 때 실측값으로 보정하는 방식으로 완화한다.

## 요약

윈도잉은 "렌더링 단위를 얼마나 잘게 쪼갤 것인가"의 트레이드오프다: 단위↓ → 변경 전파 범위·기능 granularity 개선, 관리 조각 수·높이 추정 부담 악화.
