# 미션 1 — 구조적 타이핑의 함정

리뷰에서 본 예시(`printPosition`에 여분 프로퍼티 `z`가 있는 객체를 넘기는 것)를 살짝 비틀었다.
`mission.ts`에 미션 A와 미션 B가 있는데, **둘 다 완전히 같은 모양의 데이터**를 넘긴다. 차이는 딱 하나 — A는 객체 리터럴을 그 자리에서 바로 넘기고, B는 변수에 담았다가 넘긴다.

## 예상해보기
컴파일해보기 전에 먼저 답해보기:
- A(리터럴 직접 전달)는 통과할까, 에러가 날까?
- B(변수 경유)는?
- 구조적 타이핑이 "이름 말고 구조로 판단한다"는 원칙대로면 A, B 둘 다 같은 결과가 나와야 하지 않을까?

## 실행
```bash
tsc mission.ts --strict --noEmit
```

## 확인할 포인트
에러가 어느 줄에서 나는지, 몇 개나 나는지 확인해봐. 두 줄 다 같은 결과가 아니라는 게 핵심이다.

**힌트**: TS는 "구조적 타이핑"과는 별개로, **객체 리터럴을 함수에 직접 넘길 때만** 추가로 "여분 프로퍼티 검사(excess property check)"라는 걸 한다. 변수를 경유하면 이 검사가 빠지고 순수한 구조적 타이핑(부분집합만 맞으면 통과)만 적용된다. 리뷰 원문의 예시(`myObj`를 변수로 만들어서 넘김)가 통과했던 게 우연이 아니라 이 규칙 때문이었다는 걸 이번 미션으로 확인하는 것.
