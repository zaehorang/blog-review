# 05. CSRF 공격 → 방어

> 어느 리뷰에서: [`../../../reviews/2026-08-04-oliveyoung-vue-web-components.md`](../../../reviews/2026-08-04-oliveyoung-vue-web-components.md)

교육 목적, **localhost 안에서만** 동작합니다. 리뷰에서 "쿠키 기반 인증은 CSRF 방어(토큰·Origin 검증)를 부모 시스템이 별도로 갖춰야 한다"고 한 부분의 실물.

## 확인하는 것
로그인 쿠키만 있으면 다른 사이트가 내 의지 없이 이체를 발생시킬 수 있다는 것(공격 성공), 그리고 CSRF 토큰 검증이 그걸 막는다는 것(방어 성공).

## 실행
터미널 두 개:
```bash
# 터미널 1
node bank-server.js

# 터미널 2
node attacker-server.js
```

## 순서
1. http://localhost:5801/login 방문 → 로그인.
2. http://localhost:5801 방문 → 잔액 100000원 확인.
3. **새 탭**에서 http://localhost:5802 방문 (그냥 열기만 하면 됨).
4. 다시 http://localhost:5801 새로고침 → **🚨 잔액이 50000원 줄어있음.** 방문만 했는데 이체가 실행된 것 — 브라우저가 쿠키를 자동으로 실어 보냈기 때문.
5. http://localhost:5802 에서 "방어된 엔드포인트도 공격해보기" 버튼 클릭 → **✅ 거부됨** (CSRF 토큰이 없어서).
6. http://localhost:5801의 "정상 이체" 폼(진짜 토큰 포함)으로 이체 → 정상 처리되는 것도 비교.

## 왜
브라우저는 쿠키를 "누가 요청을 보냈는지"와 무관하게 **도메인만 보고 자동으로 실음**. 서버가 "이 요청이 진짜 내 페이지에서 왔는가"를 CSRF 토큰으로 직접 확인해야만 막을 수 있다는 것.
