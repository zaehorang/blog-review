# Samsung — WOA Agent: Wear OS 이슈 초도 분석 자동화

## 🔑 한 줄 요약
> 규칙이 명확한 일(파일 수집·압축 해제·복호화)은 코드로, 해석이 필요한 일은 LLM으로 갈라야 신뢰가 생긴다 — 그리고 그 신뢰의 핵심은 "빠른 답"이 아니라 **"모를 땐 모른다고 말하는 능력"**이다.

## 📌 무슨 글
- Galaxy Watch 검증 단계에서 나오는 크래시/ANR/화면 흑화 이슈는, 개발자가 실제 분석 전에 파일 다운로드·압축 해제·로그 복호화·유사 이슈 검색으로 약 30분을 쓴다.
- 이 준비 과정을 이벤트 기반으로 자동화한 "WOA Agent"를 만든 경험담. 전처리는 결정적 코드, 해석은 이슈 유형별 프롬프트를 가진 코딩 에이전트(Cline), 유사 이슈 검색은 RAG.
- 결과: 준비 시간 30분 → 5분.

## 🧠 내가 이해한 것 → 교정

**① 코드 vs LLM 역할 분담**
- 내 생각: 사람 판단이 필요 없는 과정을 에이전트에 위임한다 → deterministic한 과정을 찾으면 된다.
- 🔧 교정: 두 축을 하나로 합쳤다. 실제 분리는 3단이다 — **규칙 명확 → 코드 / 해석 필요 → LLM / 최종 결론 → 사람**. 사람의 판단(중복 여부, 담당 모듈 확인)은 사라지지 않는다. 없어진 건 판단 자체가 아니라 판단하기까지 걸리던 30분.
- 💡 한 단계 더: 코드로 미는 이유가 비용(토큰)만은 아닐 수 있다. LLM 추론 시간은 입력 복잡도에 따라 **비결정적으로 늘어나는 자원**이다. 실시간 파이프라인에서 이건 타임아웃 리스크로 이어지므로, "토큰 비용 절감"과 같은 논리로 "지연시간의 비결정성 제거"도 전처리를 코드로 뺀 이유였을 가능성이 있다.

**② "모른다고 말하는 능력" — 커버 범위**
- 내 생각: LLM은 값이 없어도 어떻게든 응답하려 하므로 명시적 stop point가 필요하다.
- ✅ 맞음, 이게 글 제목("분석할 수 없음부터 가르치세요")의 핵심이다. LLM은 "응답 거부"보다 "그럴듯한 응답"이 항상 손실이 낮게 학습되므로, "모른다"는 기본값이 아니라 명시적으로 부여해야 하는 능력이다.
- 💡 한 단계 더: 이 능력이 막아주는 건 **정보가 아예 불충분한 경우**(로그 미도착 등)다. 근거는 있는데 유사 이슈 매칭이 틀리는 **"그럴듯한 오판"**은 다른 실패 모드라 이 장치로는 안 막힌다. 두 실패 모드를 구분해서 봐야 뭘 커버하고 뭘 못 커버하는지 선명해진다.

**③ 신뢰는 구조만으로 완성되지 않는다**
- 내 생각: LLM이 근거를 던지고 판단은 사람이 하므로, 단순히 믿는 구조가 아니다.
- 🔧 교정: 역할이 나뉘어 있다는 건 설계 의도일 뿐 실제로 안 믿는다는 보장은 아니다 → [Automation bias](../concepts/automation-bias.md). 결과가 대체로 맞아떨어지기 시작하면 사람은 근거를 형식적으로만 훑고 결론을 그대로 받아들이는 경향이 생긴다. 역할 분리는 안전장치의 필요조건이지 충분조건이 아니다.

**④ 플랫폼 간 이식성**
- 내 생각: 플랫폼마다 흔한 이슈 유형이 다르니(서버는 다운 등), 그 단계에서 분석 순서/근거만 따로 나누면 이식된다.
- ✅ 맞음 — 정확히 글의 "이슈 유형별 프롬프트 분리"를 일반화한 것.
- 💡 한 단계 더: 옮기기 어려운 건 프롬프트가 아니라 **전처리(코드) 레이어**다. 로그 포맷·저장 위치·인코딩은 플랫폼마다 완전히 다르므로, LLM 프롬프트 교체는 싸고 전처리 코드 재구축은 비싸다. 이식 가능한 건 "설계 원칙"이지 "구현"이 아니다.

## 🔁 도메인 안 가리는 패턴
1. 자동화할 프로세스를 해부해 **"규칙이 명확한 것"과 "해석이 필요한 것"**으로 가르고, 전자만 코드로 내린다. 비결정성이 쌓인 단계가 많을수록, 장애가 났을 때 원인을 좁혀야 할 구간도 늘어난다.
2. 판단을 위임하는 시스템의 신뢰는 **구조(형식·근거 제시)로 시작**하지만, 사람이 그 근거를 실제로 검증하게 만드는 장치 없이는 완성되지 않는다.
3. 안전장치는 실패 모드별로 따로 필요하다 — "정보 부족"엔 정지 능력이 답이지만, "그럴듯한 오판"엔 다른 장치가 필요하다. 하나로 뭉치면 뭘 못 막는지가 안 보인다.
4. 설계 원칙은 도메인을 넘어 이식되지만, 규칙 기반 전처리 구현은 도메인에 강하게 결합돼 있어 이식 비용이 원칙과 다르다.

## 📚 이 글로 정리한 개념
- [Automation bias (자동화 편향)](../concepts/automation-bias.md) — 이 글의 "근거 제시 + 사람 판단" 구조가 실제로 신뢰를 담보하는지 짚을 때 필요했던 개념.

## 🎯 오늘 챙길 한 줄
